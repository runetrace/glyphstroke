# Glyphstroke

Жесты мыши для Linux в духе StrokeIt и Symbol Commander: удерживаете правую
кнопку, чертите на экране знак, отпускаете — выполняется привязанное
действие. Обычный правый клик при этом продолжает работать, контекстное меню
не мигает.

Написано под Ubuntu, работает **и в X11, и в Wayland**: перехват идёт на
уровне ядра через `evdev`/`uinput`, а не через X-сервер. Этим оно отличается
от easystroke, который живёт только в X11.

![редактор жестов](docs/editor.png)

## Что умеет

* Росчерк правой (или средней, боковой) кнопкой запускает действие.
* Два способа задать жест: **нарисовать образцы** (алгоритм $1 Unistroke
  сравнивает форму) или **написать код направлений** вроде `D-R` — «вниз,
  потом вправо».
* Действия: стандартное действие системы из списка, команда оболочки,
  комбинация клавиш, ввод текста, щелчок
  кнопкой мыши, прокрутка, пауза — по несколько подряд.
* Жест может открывать **меню** — список действий у курсора, если задать
  ему пункты; без пунктов всё как раньше.
* Жест можно ограничить приложением (в X11, sway, Hyprland).
* **Наборы жестов**: несколько наборов с переключением целиком — обычный,
  игровой, рабочий.
* Графический редактор жестов, запись росчерков прямо в окне; настройки
  программы — отдельным окном, разбитые на группы.
* Выгрузка и загрузка всех жестов одним файлом.
* Перехват можно приостановить — из панели, из редактора или командой.
* **Отключение в полноэкранных приложениях**: пока запущена игра или идёт
  видео во весь экран, мышь отпускается сама.
* Интерфейс на английском и русском, язык берётся из системы.
* Нераспознанный росчерк по умолчанию возвращает приложению обычный клик —
  ничего не теряется.
* След за курсором во время рисования: в X11 рисует само приложение, в GNOME
  на Wayland — расширение оболочки из комплекта.

## Системные требования

- Сеанс X11 или Wayland.
- Python 3.9 или новее.
- Обязательно: `python3-evdev`, `python3-yaml`.
- Для редактора и следа в X11: `python3-gi`, `gir1.2-gtk-3.0`,
  `python3-gi-cairo`.
- В GNOME на Wayland след, меню жеста и выбор окна рисует расширение оболочки —
  демон ставит его в домашний каталог сам.
- Доступ к устройствам ввода: членство в группе `input` и модуль `uinput`. Всё
  это настраивают пакет `.deb` и `install.sh`.

## Установка

```bash
git clone <репозиторий> glyphstroke-linux
cd glyphstroke-linux
./install.sh          # зависимости, /opt/glyphstroke, udev, группа input, значок
```

Установщик всё делает сам: ставит зависимости, выдаёт доступ к мыши, включает
автозапуск, а расширение оболочки для GNOME кладёт себе демон при первом
запуске. От вас нужен один шаг, и обойти его нельзя: **выйдите из системы и
войдите снова** — группа `input` подхватывается только при входе, а расширения
GNOME загружает только при старте сеанса.

Дальше при желании:

```bash
glyphstroke doctor          # проверка прав и поиск мышей
glyphstroke bind            # слушать только одну мышь (если она одна — привяжется сразу)
glyphstroke gui             # редактор жестов
```

Удаление: `./uninstall.sh` (настройки в `~/.config/glyphstroke` остаются).

### Обновления

Раз в сутки программа спрашивает страницу выпусков, не вышла ли версия новее.
Вышла — редактор показывает полоску, `glyphstroke doctor` строку, `glyphstroke update`
проверяет сейчас. Сама программа не обновляется: перехват мыши — не то место,
где уместна тихая подмена, ставит новую версию человек.

Проверку видно и можно выключить: переключатель в настройках редактора (группа
«Программа») или `check_updates: false` в `settings.yaml`. Откуда брать
выпуски, задаёт `update_repo` — «владелец/хранилище» на GitHub.

### Пакет .deb

```bash
./packaging/build-deb.sh                       # соберёт dist/glyphstroke_ВЕРСИЯ_all.deb
sudo apt install ./dist/glyphstroke_1.0.10_all.deb
```

Пакет кладёт код в `/usr/lib/glyphstroke`, команды `glyphstroke` и `glyphstroked` — в
`/usr/bin`, а ярлык, значки, правило udev и документацию — по их обычным
местам; зависимости доставит apt. Дальше остаётся дать себе группу `input` и
перезайти в систему — об этом пакет напоминает при установке. Удаление
обычное: `sudo apt remove glyphstroke`, настройки при этом остаются.

При установке поверх прежней версии пакет напомнит перезапустить службу и
заново поставить расширение оболочки: GNOME загружает его копию из домашнего
каталога, и обновление пакета эту копию не трогает. `glyphstroke doctor` заметит и
старый демон, и устаревшее расширение.

Для сборки нужен только `dpkg-deb`: пакет собирается из готового дерева, без
debhelper и правил `debian/rules`. Версия берётся из `glyphstroke/version.py`.

### Без установщика

```bash
sudo apt install python3-evdev python3-yaml python3-gi gir1.2-gtk-3.0 python3-gi-cairo
sudo usermod -aG input "$USER"     # затем перезайти в систему
python3 -m glyphstroke.cli init
python3 -m glyphstroke.daemon         # запуск в терминале
```

## Набор жестов по умолчанию

| Росчерк | Код | Действие |
|---|---|---|
| влево | `L` | Назад (`alt+Left`) |
| вправо | `R` | Вперёд (`alt+Right`) |
| вверх | `U` | Новая вкладка (`ctrl+t`) |
| вниз | `D` | Закрыть вкладку (`ctrl+w`) |
| вниз, затем вправо | `D-R` | Закрыть окно (`alt+F4`) |
| вниз, затем влево | `D-L` | Терминал |

Ещё один жест — «Обновить страницу» — выключен и лежит как пример привязки
к конкретным приложениям.

## След за курсором

Линия под курсором рисуется, пока удерживается кнопка-модификатор. Способ
зависит от сеанса, потому что права на «нарисовать поверх всех окон» и «узнать
позицию курсора» выданы по-разному:

| Сеанс | Кто рисует | Что нужно сделать |
|---|---|---|
| X11 | окно самого демона | ничего, работает сразу |
| GNOME на Wayland | расширение оболочки | ничего: демон ставит расширение сам, нужен перезаход |
| sway, Hyprland и прочий Wayland | пока никто | след недоступен, жесты работают |

Вид линии задаётся в настройках редактора — цвет, толщина и непрозрачность, с
образцом рядом — или прямо в `settings.yaml`:

```yaml
overlay:
  enabled: true
  color: "#4da3ff"
  width: 4
  opacity: 0.9     # 0…1, где 1 — сплошная линия
  fade_ms: 220     # сколько след гаснет после отпускания
```

Расширение ставит сам демон при запуске: он сверяет версию своей копии в
`~/.local/share/gnome-shell/extensions` с той, что пришла с программой, и
обновляет её, когда та устарела. Так и задумано, что руками делать нечего —
установщику пакета до чужого домашнего каталога и сессионной шины не
дотянуться, а демон уже работает в сеансе пользователя. Единственное, что
остаётся человеку, — перезайти в систему: новые расширения оболочка загружает
только при старте сеанса.

Команды на случай, если хочется вмешаться:

```bash
glyphstroke shell-extension status    # состояние расширения и канала связи
glyphstroke shell-extension install   # поставить и включить прямо сейчас
glyphstroke shell-extension remove
```

Расширение делает три вещи: рисует след, нажимает клавиши и работает с окнами
вместо демона, а ещё добавляет значок в верхнюю панель с переключателем
перехвата.

Расширение оболочка загружает при запуске, поэтому после установки нужно
выйти из системы и войти снова. `install.sh` ставит его сам, если в системе
есть GNOME.

Демон объявляет о начале и конце росчерка в сокете
`$XDG_RUNTIME_DIR/glyphstroke/overlay.sock`, а рисовальщик подключается к нему
как клиент. Демону всё равно, слушает его кто-нибудь или нет, поэтому
отсутствие расширения ни на что не влияет.

## Меню под жестом

Меню — необязательная добавка к жесту. Пока пунктов нет, ничего не меняется:
жест выполняет свои действия. Как только на вкладке «Меню» в редакторе
появился хотя бы один пункт, тот же росчерк открывает у курсора список — одна
фигура вместо десятка запомненных росчерков.

```yaml
name: Правка
directions: [U]
actions: []                # свои действия можно не задавать вовсе
menu:
  - name: Копировать
    actions:
      - {type: keys, value: ctrl+c}
  - name: Вставить
    actions:
      - {type: keys, value: ctrl+v}
```

Пока меню открыто, мышь принадлежит ему: до системы не доходят ни движения,
ни щелчки. Поэтому курсор стоит на месте, а пункт выбирается по пройденному
пути — шаг вниз на пункт (`menu_step_px`). Колесо тоже ходит по списку.

| Что сделать | Что будет |
|---|---|
| вести вниз | подсвечивается следующий пункт |
| вести вверх, к месту жеста | не выбрано ничего |
| отпустить левую кнопку | выполняется подсвеченный пункт |
| отпустить правую (любую другую) | меню закрывается, ничего не выполняется |
| замереть на `menu_timeout_ms` | меню закрывается само |

Подсветку задаёт демон, а рисует список расширение оболочки (в X11 — окно
следа), поэтому картинка не может разойтись с тем, что на самом деле
выполнится. Если рисовать некому — расширение не поставлено, а след выключен, —
меню не открывается: жест просто выполняет свои действия, а в журнале
появляется предупреждение. Кто именно нарисует меню, показывает `glyphstroke doctor`.

## Пауза

Иногда перехват мешает — например, в программе, где правая кнопка нужна
целиком. Тогда его можно отпустить, не выключая службу:

```bash
glyphstroke pause     # мышь отпущена, правая кнопка работает как обычно
glyphstroke resume
glyphstroke toggle
```

На паузе демон именно снимает захват устройства, а не пересылает события мимо
себя, поэтому мышь ведёт себя ровно как без нашей программы.

То же самое делает переключатель «Перехват жестов» в настройках редактора и
значок в верхней панели GNOME — он появляется вместе с расширением оболочки.
В его меню есть переключатель перехвата, текущее состояние и запуск редактора;
значок меняется, когда перехват приостановлен.

### Полноэкранные приложения

Настройка «Отключаться в полноэкранных» (`pause_in_fullscreen`) снимает
перехват, пока активное окно развёрнуто во весь экран: в игре мышь должна
принадлежать игре. Выйдете из неё — перехват вернётся сам.

Признак «во весь экран» — это обычное свойство окна, и берётся оно оттуда же,
откуда программа узнаёт активное окно: в X11 через `_NET_WM_STATE`, в sway и
Hyprland — их родными командами, а в GNOME про него сообщает расширение
оболочки. Там, где узнать неоткуда, настройка просто ничего не делает.

Пауза, снятая или возвращённая руками, старше нашей: если вы вернули перехват
прямо в игре, отбирать его обратно программа не станет.

## Перенос жестов

Все жесты вместе с действиями складываются в один файл — удобно перенести
настройку на другую машину или сохранить перед экспериментами:

```bash
glyphstroke export ~/жесты.yaml                  # только жесты
glyphstroke export ~/всё.yaml --with-settings    # вместе с настройками
glyphstroke import ~/жесты.yaml                  # добавить, совпадающие заменить
glyphstroke import ~/жесты.yaml --replace        # точная копия: прежние убрать
```

В редакторе это кнопки «Выгрузить в файл…» и «Загрузить из файла…» в окне
настроек (шестерёнка в шапке), группа «Программа». При загрузке жесты с совпадающими названиями заменяются, а о
занятых кодах направлений программа предупредит.

## Окно, над которым рисуют

Правый клик демон придерживает, поэтому окно под курсором само по себе фокус
не получает — и сочетание клавиш ушло бы в то окно, которое было активным
раньше. На двух экранах это заметно сразу: рисуете на втором, а срабатывает
на первом.

Поэтому расширение оболочки запоминает окно под курсором **в момент нажатия**
кнопки и перед выполнением действия делает его активным. Отключается
параметром `focus_under_cursor` в настройках.

Действия над самим окном не требуют сочетаний клавиш вообще:

```yaml
actions:
  - {type: window, value: minimize}
```

Понимает `minimize`, `maximize`, `unmaximize`, `close`, `fullscreen`,
`unfullscreen`, `activate`, `above`, `unabove`. Всё это делает расширение
оболочки; в X11 без него `minimize`, `close` и `activate` подхватит `xdotool`,
если он установлен. В комплекте есть выключенный пример — жест «Свернуть окно».

## Клавиши и раскладка

Действие типа `keys` можно отправить двумя способами, и разница видна только
при нелатинской раскладке.

**Через uinput** — демон нажимает клавиши кодами, на уровне ядра. Композитор
читает код через текущую раскладку: при русской `KEY_C` превращается в «с»,
и приложение не узнаёт в этом `Ctrl+C`. Стрелки, `F5` и прочие клавиши без
буквы работают в любой раскладке, а вот `ctrl+c`, `ctrl+w`, `ctrl+t` — только
в латинской.

**Через расширение оболочки** — оно шлёт не код клавиши, а символ, поэтому
раскладка перестаёт что-либо значить. Расширение то же самое, что рисует
след: подключаясь к демону, оно сообщает, что умеет нажимать клавиши, и демон
отдаёт сочетания ему.

Выбор задаёт `keys_via` в настройках: `auto` (по умолчанию — через расширение,
если оно на связи, иначе uinput), `uinput` или `shell`. Что сработало на самом
деле, показывает `glyphstroke watch`:

```
код U            → «Копировать» (1.00)
  выполнено: keys ctrl+c, клавиши через оболочку
```

## Особые жесты: rocker и колесо

Не всякий жест нужно рисовать. Два вида срабатывают сразу:

| Событие | Что сделать |
|---|---|
| `rocker-left` | удерживая правую кнопку, щёлкнуть левой |
| `rocker-right` | удерживая левую, щёлкнуть правой |
| `wheel-up`, `wheel-down` | колесо при зажатой кнопке-модификаторе |
| `wheel-left`, `wheel-right` | горизонтальное колесо |

В файле жеста вместо росчерка пишется событие:

```yaml
name: Назад
event: rocker-left
actions:
  - {type: keys, value: alt+Left}
```

В редакторе это список «Тип жеста». Щелчок и прокрутка, ставшие жестом, до
приложения не доходят: страница не прокручивается, лишнего клика нет. Если
событие ни к чему не привязано, всё работает как обычно. В наборе лежат
четыре выключенных примера.

## Подсказки на экране

- **Имя сработавшего жеста** показывается плашкой — сразу видно, что
  распозналось. Отключается параметром `show_gesture_name`.
- **Шпаргалка**: удержите кнопку, не двигая мышью, и появится список жестов с
  тем, как каждый сделать. Задержка задаётся `hint_delay_ms`, ноль выключает.

В X11 то и другое рисует само приложение, в GNOME на Wayland — расширение
оболочки: имя показывается штатным экранным индикатором, шпаргалка — панелью
по центру экрана.

## Рисование на тачпаде

На ноутбуке жест рисуется пальцем: зажмите Super и ведите пальцем по
тачпаду. Росчерк начинается касанием при зажатой клавише и заканчивается
отрывом пальца или отпусканием клавиши — что случится раньше. Касание двумя
пальцами росчерком не считается, это прокрутка.

Клавиша задаётся в настройках, в группе «Тачпад»: из списка или нажатием
любой клавиши. В файле настроек это выглядит так:

```yaml
touchpad_key: KEY_LEFTMETA   # пусто — рисование на тачпаде выключено
```

Тачпад не захватывается: курсор идёт за пальцем, как за мышью при обычном
жесте, и след рисуется за курсором. Прокрутка, жесты оболочки и отсечение
ладони остаются при тачпаде. Клавиатуру демон тоже не захватывает: он читает
её и следит за одной назначенной клавишей, остальные нажатия проходят мимо,
не запоминаясь и не попадая в журнал. Клавиатуры читаются, только когда в
системе есть тачпад.

Меню под жестом водят пальцем, а выбирают отрывом пальца на нужном пункте.
Щелчок по тачпаду для выбора не годится: тачпад не захвачен, и щелчок ушёл
бы приложению под курсором.

Одиночный Super в GNOME открывает обзор, когда клавишу отпускают. После
росчерка этого не происходит: демон сообщает расширению оболочки, что Super
занят росчерком, и расширение пропускает одно открытие обзора. В других
окружениях Super может открыть их меню — там удобнее назначить другую
клавишу.

Мышь демону не обязательна: на ноутбуке с одним тачпадом он запускается и
так.

## Одна мышь вместо всех

По умолчанию демон перехватывает все найденные мыши. Если мышь одна или нужна
конкретная, привяжитесь к ней:

```bash
glyphstroke bind                 # мышь одна — привяжется молча
glyphstroke bind --ask           # нажмите кнопку на нужной мыши
glyphstroke bind --clear         # обратно ко всем мышам
```

То же самое делает кнопка «Определить» в окне настроек редактора, группа
«Мышь»:

![настройки](docs/settings.png)

Привязка сохраняется постоянной ссылкой `/dev/input/by-id/...`, которая
строится по производителю, модели и серийному номеру, поэтому переживает
перезагрузку и смену разъёма. Если такой ссылки нет, берётся `by-path`, а в
последнюю очередь — имя устройства.

## Как жест узнаётся

Способа два, и они независимы.

**Образцы росчерков.** Нарисованное приводится к 64 равноудалённым точкам,
нормализуется по размеру и положению и сравнивается с вашими образцами
($1 Unistroke Recognizer). Сравнивается только форма: длина линии, масштаб,
место на экране и дрожание руки на результат не влияют. Так задаётся любой
жест, включая дуги, петли и буквы.

**Код направлений.** Росчерк раскладывается в строку октантов вида `D-R`.
Нужен ровно для одного — чтобы набор из коробки работал сразу, до того как вы
что-нибудь нарисовали: описать «влево» текстом дешевле, чем прикладывать чужие
росчерки. Коды сверяются не посимвольно, а с допуском: лишний соседний октант
(`L-DL` вместо `L`) почти ничего не стоит, а прыжок через октант ломает
совпадение.

В своём жесте поле кода можно оставить пустым — достаточно образцов. И
наоборот. Если жест выходит неоднозначным (нарисованное одинаково похоже на
два жеста), не срабатывает ни один: за это отвечает `min_margin`.

## Жесты для конкретного приложения

Поле «Только в приложениях» (`apps` в файле жеста) ограничивает жест. Вписывать
приложение руками не нужно: рядом с полем стоит мишень. Зажмите её, перетащите
на окно нужной программы и отпустите — класс окна попадёт в список приложений и
сразу отметится у жеста. Уже известные приложения отмечаются галочками по
кнопке «Выбрать…».

Разбор идёт в два захода — сначала жесты текущего приложения, потом общие.
Поэтому один и тот же росчерк может делать разное в разных программах:

```yaml
# общий: закрыть вкладку
name: Закрыть вкладку
directions: [D]
actions: [{type: keys, value: ctrl+w}]
---
# в редакторе кода тот же росчерк удаляет строку
name: Удалить строку
directions: [D]
apps: ["class:code"]
actions: [{type: keys, value: ctrl+shift+k}]
```

Такая пара не считается конфликтом: в своём приложении выигрывает жест
приложения, в остальных работает общий. Ссорятся только жесты с одинаковым
росчерком и пересекающейся областью — о них скажут `glyphstroke list` и `glyphstroke doctor`.

Обратное — список приложений, где перехвата не нужно вовсе. Он выбирается в
настройках точно так же, мишенью или галочками, и хранится вот так:

```yaml
excluded_apps: ["class:gimp", "class:krita"]
```

Там правая кнопка ведёт себя так, будто программы не существует: нажатие
отдаётся приложению сразу, без ожидания росчерка.

Все пойманные приложения лежат в `~/.config/glyphstroke/apps.yaml`, общем для всех
наборов, и видны в настройках, в группе «Приложения». Там их и удаляют:
привязки снимаются во всех наборах, а жест, у которого не осталось других
приложений, выключается — иначе жест «только в Firefox» заработал бы везде.
Список уезжает вместе с жестами в `glyphstroke export`.

Запись `class:имя` сверяется с классом окна целиком. Строка без пометки — это
регулярное выражение по «класс окна | заголовок», как раньше: записи из старых
файлов продолжают работать и видны в списке с пометкой «выражение». Выражение
ловит и заголовки, поэтому `code` сработает и в браузере на вкладке, в названии
которой встретилось это слово.

В GNOME на Wayland активное окно и окно под мишенью демону сообщает расширение
оболочки — без него привязка к приложениям и список исключений там не работают.
В X11 мишень обходится и без расширения.

## Наборы жестов

Набор — это все жесты разом. Пока набор один, ничего не меняется: жесты лежат
в `~/.config/glyphstroke/gestures/`, как и лежали. Второй и следующие живут в
`~/.config/glyphstroke/profiles/ИМЯ/`, и тогда в редакторе над списком появляется
выбор набора, а в терминале — команда:

```bash
glyphstroke profile                    # какие наборы есть и какой сейчас
glyphstroke profile new игры --copy    # завести копией текущего
glyphstroke profile new пустой         # завести пустым
glyphstroke profile use игры           # переключиться целиком
glyphstroke profile use основной       # вернуться к основному (годится и «-»)
glyphstroke profile remove игры        # убрать вместе с жестами
```

Переключение меняет всё сразу — и жесты, и действия. Фильтр по приложению
хорош, когда наборы отличаются парой жестов; набор — когда целиком.

Текущий набор запоминается в `settings.yaml` (`active_profile`), демон
подхватывает его при перечитывании настроек. Основной набор удалить нельзя;
если каталог набора пропал, программа молча вернётся к основному — остаться
вовсе без жестов хуже.

## Свой жест

**В редакторе** (`glyphstroke gui`): «＋», название, нарисуйте росчерк на холсте левой
кнопкой — он сразу становится образцом (2–3 росчерка, и распознавание станет
устойчивее), на вкладке «Действия» выберите, что делать, и «Сохранить жест».
Кнопка «Проверить распознавание» показывает, как оценивается нарисованное.

**В терминале**:

```bash
glyphstroke record "Свернуть всё" -n 3 --keys "super+d"
glyphstroke watch       # что распознаёт работающий демон, прямо сейчас
glyphstroke list
```

```bash
glyphstroke --version                     # версия установленного пакета
glyphstroke doctor                        # в том числе версия работающего демона
glyphstroke watch --save ~/росчерки       # сохранять росчерки в файлы
```

`glyphstroke doctor` отдельной строкой показывает версию демона, который сейчас
работает. Если она разошлась с установленной — значит, служба крутит старый
код из `/opt`, и её надо перезапустить: `systemctl --user restart glyphstroke`.

`glyphstroke watch` показывает разбор каждого росчерка — код направлений, жест и
оценку. Мышь он ни у кого не забирает: читает тот же канал, что и рисовальщик
следа. `glyphstroke record` и `glyphstroke test`, наоборот, мышь забирают, поэтому
сами останавливают службу на время работы и запускают обратно.

## Файлы настроек

`~/.config/glyphstroke/settings.yaml` — общие параметры:

| Параметр | Смысл |
|---|---|
| `trigger_button` | кнопка-модификатор: `BTN_RIGHT`, `BTN_MIDDLE`, `BTN_SIDE` |
| `capture_mode` | `grab` — перехватывать кнопку; `monitor` — только следить |
| `min_stroke_px` | короче этого пути — обычный клик, а не жест |
| `min_score` | строгость сравнения с образцом, 0…1 |
| `min_margin` | насколько лучший вариант должен опережать второй |
| `unrecognized` | `passthrough` — вернуть клик, `ignore` — съесть |
| `keys_via` | чем нажимать клавиши: `auto`, `uinput`, `shell` — см. раздел про раскладку |
| `focus_under_cursor` | делать активным окно, над которым начали рисовать |
| `excluded_apps` | приложения, где перехвата нет вовсе |
| `pause_in_fullscreen` | отпускать мышь, пока активное окно во весь экран |
| `show_gesture_name` | показывать имя сработавшего жеста |
| `active_profile` | текущий набор жестов; пусто — основной |
| `hint_delay_ms` | через сколько миллисекунд удержания показать шпаргалку |
| `menu_step_px` | сколько вести мышью вниз до следующего пункта меню |
| `menu_timeout_ms` | через сколько миллисекунд без движения меню закроется само |
| `press_passthrough_ms` | отдать нажатие приложению, если кнопку держат без движения (для right-drag в играх и CAD); 0 — выключено |
| `device_include` / `device_exclude` | отбор устройств: выражения сверяются с именем и путями, включая ссылки в `by-id`; проще задать командой `glyphstroke bind` |
| `allow_touchpads` | перехватывать и тачпады (по умолчанию нет) |
| `touchpad_key` | клавиша для рисования на тачпаде: пока она зажата, палец рисует росчерк (по умолчанию `KEY_LEFTMETA`, это Super); пусто — выключено |

`~/.config/glyphstroke/profiles/ИМЯ/` — дополнительные наборы жестов, если их
заводили; файлы там устроены так же.

`~/.config/glyphstroke/gestures/*.yaml` — по файлу на жест:

```yaml
name: Закрыть окно
enabled: true
directions: [D-R]          # код направлений; можно несколько вариантов
apps: []                   # пусто — везде; иначе "class:firefox" или выражение
rotation_tolerance: 20.0   # допуск поворота образца, градусы
actions:
  - {type: keys, value: alt+F4}
menu: []                   # пункты меню; без них ключа в файле нет вовсе
templates: []              # образцы росчерков, если рисовали руками
```

### Действия

| Тип | Значение | Пример |
|---|---|---|
| `standard` | стандартное действие системы по имени | `copy`, `paste`, `minimize` |
| `keys` | комбинация или несколько подряд | `ctrl+w`, `alt+Left`, `ctrl+c ctrl+v` |
| `command` | строка для `/bin/sh -c` | `xdg-open ~/Загрузки` |
| `app` | приложение: путь к `.desktop` или к программе | `/usr/share/applications/firefox.desktop` |
| `text` | текст для набора | `подпись` |
| `button` | кнопка мыши и число щелчков | `middle`, `back 2` |
| `scroll` | направление и число щелчков колеса | `up 3`, `down` |
| `window` | действие над окном, где начали рисовать | `minimize`, `maximize`, `close`, `fullscreen` |
| `delay` | пауза в миллисекундах | `150` |

Стандартное действие выбирается из списка в редакторе, а в файле остаётся
именем: `copy`, `paste`, `cut`, `delete`, `undo`, `redo`, `select-all`, `new`,
`open`, `save`, `print`, `find`, `new-tab`, `close-tab`, `next-tab`,
`prev-tab`, `back`, `forward`, `refresh`, `zoom-in`, `zoom-out`, `zoom-reset`,
`minimize`, `maximize`, `unmaximize`, `fullscreen`, `close-window`,
`switch-window`, `quit`, `screenshot`. Так не нужно помнить сочетания, и такой
жест переносится на другую систему как есть: там то же действие выполнится её
собственными клавишами. Таблица — в `glyphstroke/standard.py`.

Коды направлений строятся из восьми октантов: `R`, `DR`, `D`, `DL`, `L`,
`UL`, `U`, `UR` — и соединяются дефисом в порядке рисования. Круги, дуги и
буквы кодом не опишешь: для них рисуйте образцы.

## Ограничения

* **След за курсором вне X11 требует расширения оболочки.** В Wayland
  приложению не отдают ни глобальную позицию курсора, ни право нарисовать
  окно поверх всего (GNOME не поддерживает `wlr-layer-shell`). Для GNOME
  расширение есть в комплекте; в sway, Hyprland и прочих композиторах след
  пока не рисуется, жесты работают. Собственное окно демон в Wayland не
  запускает: оно подцепилось бы к Xwayland и рисовало ломаную из случайных
  координат.
* **Фильтр по приложению** работает в X11, sway и Hyprland. В GNOME на
  Wayland активное окно узнать нечем — жесты с непустым `apps` там просто не
  срабатывают, глобальные работают.
* **Тачпады** по умолчанию не перехватываются: захват тачпада лишает его
  настроек libinput (естественная прокрутка, отсечение ладони). Рисовать
  пальцем при зажатой клавише это не мешает, захват для этого не нужен.
  Перехват тачпада как мыши включается через `allow_touchpads: true`.
* **Super после росчерка по тачпаду** не открывает обзор только в GNOME с
  расширением оболочки. В KDE и других окружениях отпущенный Super может
  открыть их меню — там удобнее назначить другую клавишу.
* **Действие `text`** набирает символы по раскладке US: латиница и цифры
  везде одинаковы, знаки препинания в других раскладках могут разойтись.
  Через расширение оболочки это ограничение не действует.
* Нужна группа `input` — это доступ ко всем устройствам ввода, включая
  клавиатуру. Так работает любой перехватчик жестов под Linux.

## Если что-то пошло не так

```bash
glyphstroke doctor                          # права, устройства, зависимости
systemctl --user status glyphstroke         # состояние службы
journalctl --user -u glyphstroke -f         # что видит демон
glyphstroke daemon --dry-run                # распознавание без выполнения
glyphstroke daemon --monitor                # не перехватывать кнопку вообще
```

* **`doctor` говорит, что группа `input` не действует.** Группа выдаётся при
  входе в систему, поэтому после `usermod` нужно выйти и войти снова —
  перезапуска терминала мало. В текущем терминале проверить можно через
  `newgrp input`, но служба `systemd --user` всё равно подхватит группу
  только после перезахода.
* **Жест не срабатывает, хотя он есть в списке.** Скорее всего, его код
  направлений занят ещё одним жестом: нарисованное одинаково похоже на оба, и
  не срабатывает ни один. `glyphstroke list` и `glyphstroke doctor` показывают такие
  пары, а в редакторе они помечены знаком `⚠`.
* **Курсор подёргивается.** Убедитесь, что стоит свежая версия: раньше демон
  раз в две секунды обходил все устройства ввода прямо в потоке пересылки
  событий. Дополнительно помогает привязка к одной мыши — `glyphstroke bind`.
* **Сочетания с буквами не срабатывают, а со стрелками работают.** Это
  раскладка: демон нажимает клавиши кодами, и при русской раскладке `ctrl+c`
  приходит приложению как `ctrl+с`. Поставьте расширение оболочки — оно шлёт
  символы, а не коды: расширение ставится вместе с программой, достаточно
  перезайти в систему. Проверить, каким путём ушли клавиши, можно в `glyphstroke watch`.
* **След не рисуется в GNOME.** Проверьте `glyphstroke shell-extension status`:
  расширение должно быть включено, а канал — открыт (то есть демон запущен).
  Свежепоставленное расширение оболочка загрузит только после перезахода
  в систему. Если состояние «не установлено» — демон ни разу не запускался:
  `glyphstroke service enable`.
* **Мышь перестала слушаться.** Захват снимается вместе с процессом:
  `systemctl --user stop glyphstroke` или `pkill -f glyphstroke.daemon` с
  клавиатуры вернёт всё как было.
* **Установщик остановился на шаге «Зависимости».** Так бывает на снятых с
  поддержки выпусках Ubuntu: зеркала пусты, `apt-get update` возвращает
  ошибку. Установщик такую ошибку переживает и сам скажет, чего именно не
  хватает; самый быстрый обход —
  `sudo apt-get install -y python3-pip && sudo pip3 install --break-system-packages evdev PyYAML`,
  затем повторить `./install.sh`.
* **Жесты не ловятся, а меню выскакивает.** Демон не запущен или не нашёл
  мышь — смотрите `glyphstroke doctor` и `glyphstroke devices`.
* **Срабатывает не тот жест.** Поднимите `min_score` и `min_margin` или
  добавьте образцов: `glyphstroke record "Имя" -n 5`.
* **Жест срабатывает при обычном клике.** Увеличьте `min_stroke_px`.

## Язык интерфейса

По умолчанию программа говорит по-английски; русский включается сам, если
система русская. Выбрать язык принудительно можно в настройках редактора или
в `settings.yaml`:

```yaml
language: auto   # auto | en | ru
```

Устроено это так: строки в коде русские и служат ключами, а перевод лежит
рядом в `glyphstroke/locale/en.po` — обычный формат gettext. Читает его сама
программа, поэтому ни msgfmt при сборке, ни двоичных каталогов в репозитории
не нужно. Чтобы добавить язык, достаточно положить рядом `<код>.po` с теми же
ключами.

Названия стартовых жестов переводятся один раз — при создании набора: это
файлы пользователя, и менять их на лету нельзя. Справка лежит двумя файлами,
`help.en.md` и `help.ru.md`. У расширения оболочки свои строки и своя
маленькая таблица переводов.

Полнота английского каталога проверяется тестом: если в коде появится строка
без перевода, тест об этом скажет.

## Справка внутри программы

```bash
glyphstroke help                 # всё целиком
glyphstroke help действия        # один раздел
```

То же самое читается в окне: кнопка со знаком вопроса в заголовке редактора
открывает справку с оглавлением по разделам.

## О программе

Версия, дата обновления, автор и почта собраны в одном месте — в диалоге
«О программе» (кнопка с вопросительным знаком в заголовке редактора) и в
команде:

```bash
glyphstroke about
```

Команда печатает ещё и окружение: тип сеанса, состояние демона, каталог
настроек, состояние расширения. Этот вывод стоит прикладывать к письму об
ошибке — половина вопросов отпадает сразу. В диалоге для этого есть кнопка
«Написать об ошибке»: она открывает письмо с уже подставленными сведениями.
